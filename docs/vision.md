# 项目目标与最终效果

## 一、为什么做

辞达把「选中文字 → 一个快捷键 → 结果」这条路做得很顺：面板不抢焦点，选区自动带入，截图和原处翻译覆盖了读不到文字的地方。高强度使用之后，几个需求它满足不了：

1. **Markdown 不渲染。** 粘贴或生成的表格、代码块、列表都以原始符号显示。辞达的结果栏是为「排好版的译文」设计的纯文本管线，加 Markdown 要重写渲染核心。
2. **只能处理，不能对话。** 辞达的提示词合约把输入一律当作「待处理的材料」，不当作指令，所以快速提问、追问、让它「再精简一点」都做不了。
3. **场景比翻译和润色多。** 整理混乱文本、和 Claude Code 之间的中英转译、把口述的需求梳理成提示词，都需要不同的提示词、不同的输出格式，有时还要不同的模型。
4. **只有一个模型。** 快速问答要快和便宜，整理和转译要强，一个配置兼顾不了。

辞达的上游迭代很快，以上几点又碰到它的设计前提，fork 维护的代价高于重写（见 [决策记录](decisions.md) D1）。

## 二、目标

**一句话：任何地方，一个快捷键，把手头的文字交给合适的模型，用合适的方式处理，结果可以直接用，也可以接着聊。**

具体目标：

1. **完整替代辞达。** 辞达的四个入口（⌥A 面板、⌥F 原处改进、⌥S 截图翻译、⌥D / ⌥⇧D 原处翻译）、命令行配置、钥匙串、无历史的隐私承诺都保留，体验不低于辞达。
2. **模式化。** 把「动作」扩展成「模式」：每个模式决定输入怎样理解、用什么提示词、用哪个模型、结果怎样呈现、结果去哪里。内置翻译、改进、整理、Agent 转译、提示词梳理、问答六个模式，也能自定义。
3. **Markdown 一等公民。** 结果按 GFM 流式渲染：表格、代码块（带高亮）、任务列表、引用、链接、公式；半截的语法在流式中就按最终样式显示，不闪烁。
4. **多轮对话。** 每个结果都能追问；问答模式直接以对话开始，体验类似 Raycast AI Chat。会话只在内存里，不落盘。
5. **多模型。** 可以配置多个模型，每个模式指定默认模型。
6. **原生、轻、快。** 单一 Go 二进制，不抢焦点，唤起即现，常驻内存小。

## 三、设计原则

- **入口比功能重要。** 唤起要比任何动效都快；带入选区、截图、原处翻译这些入口的细节（不抢焦点、剪贴板原样放回、不碰原应用）是这个应用的核心价值，照辞达的标准做。
- **模式而不是聊天窗口。** 绝大多数时候用户要的是「把这段文字变成那样」，不是开一个对话。对话是结果之后的延伸，不是起点（问答模式除外）。
- **结果可以直接用。** 复制出来的东西不需要再手工清理：Markdown、纯文本、富文本按去处选择；Agent 转译保留代码、路径、命令原样。
- **本地能确定的不交给模型。** 终端输出的框线和硬换行、截图识别的拼行、语言判断，用确定的规则在本机做，省 token 也更稳。
- **不存东西。** 不保存会话和原文，日志里没有文字，API Key 只在钥匙串。
- **权限可选。** 没有辅助功能或屏幕录制权限时降级可用，不强求。

## 四、最终效果

### 面板

```
┌────────────────────────────────────────────────────────────────────┐
│ 原文 / 问题（多行输入，可粘贴、可听写）                                 │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 翻译成 English · 改进 · 整理 · Agent · 提示词 · 问答   ⇥     执行 ⏎   │
├────────────────────────────────────────────────────────────────────┤
│ 结果                                    模型 · Sonnet   复制 ⌘C ⌄   │
│                                                                    │
│ ## 会议纪要整理                                                      │
│ | 事项 | 负责人 | 截止 |                                              │
│ |------|-------|------|      ← Markdown 流式渲染，纸面底色             │
│ ...                                                                │
│                                                                    │
│ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
│ 追问…                                                     ⌘⏎ 发送   │
└────────────────────────────────────────────────────────────────────┘
```

- 宽度固定，顶边固定只向下生长，到上限后结果栏内部滚动；出现在鼠标所在屏幕。
- 第一轮之后，结果栏变成对话流：每一轮是「追问 + 回复」，最新一轮在下面；底部是追问输入框。
- 问答模式下，原文栏就是提问框，⏎ 直接开始对话。

### 一天里怎么用它

| 时刻 | 操作 | 发生什么 |
| --- | --- | --- |
| 读英文文档 | 选中一段，⌥A | 面板带着这段出现，用默认模式（翻译）译成中文 |
| Slack 上读不懂的一条消息 | 指着它按 ⌥D | 这一段就地换成译文，再按换回 |
| 刷一个日文频道 | ⌥⇧D | 整个窗口的外文段落换成译文，新消息继续翻译 |
| 图片里的图表 | ⌥S，框选 | 本机识别文字，带进面板翻译 |
| 一段从聊天记录复制的乱文本 | 粘进面板，Tab 到「整理」 | 译成中文并整理成标题、列表和表格 |
| Claude Code 回了一大段英文 | 选中终端里的输出，⌥A，Tab 到「Agent」 | 去掉框线和硬换行，译成中文，代码、路径、命令原样保留 |
| 想用中文给 Claude Code 提需求 | 在面板里写或口述中文，「Agent」模式 | 译成写给 Coding Agent 的英文，复制后粘回终端 |
| 脑子里有个模糊的需求 | 打开面板，按 Fn Fn 口述，「提示词」模式 | 梳理成「背景 / 目标 / 约束 / 验收」结构的提示词 |
| 突然想确认一个命令的用法 | ⌥A，Tab 到「问答」，输入问题 | 快速模型几秒内回答；不够清楚就追问 |
| 写邮件时想润色一句 | 选中，⌥F | 原处替换成润色后的文字，⌘Z 可撤销 |

### 成功的标准

- 辞达可以卸载：四个入口的日常使用不再需要它。
- 六个内置模式覆盖上表的场景，结果复制出来不需要手工清理。
- 唤起、带入选区、流式输出的手感与辞达相当或更好（量化指标见 [需求](requirements.md) §五）。
