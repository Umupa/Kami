# 项目目标与最终效果

## 一、为什么做

日常处理文字时，复制到另一个窗口、选择模型、补充提示词会打断手头的工作。Gloss 把这些步骤放进一个随时唤起的面板，围绕四个需求设计：

1. **结果直接可读。** 表格、代码块、列表按 Markdown 渲染，流式输出时也保持稳定。
2. **处理完可以接着问。** 翻译和润色把输入当材料，问答把输入当指令，每个结果都能继续追问。
3. **场景可扩展。** 翻译、润色、提示词梳理和问答共用一条处理管线，新增场景只需添加提示词预设。
4. **模型各司其职。** 快速问答重视延迟和成本，复杂整理重视能力，各模式可以使用不同的模型。

项目使用 Go 和 MyGo 独立实现（见 [决策记录](decisions.md) D1）。

## 二、定位

**我自己的桌面 AI 工具箱。** 一期把文字处理与对话合进一个面板：

- **快捷翻译**：选中文字或截图，一个快捷键得到译文。
- **快速问答**：随时唤起，直接提问，接着追问。

二期加入**笔记**：随手记一笔的草稿纸，在面板里 Tab 切过去就写，自动保存，可以有很多张；不接模型（见 [需求](requirements.md) F12）。

自用工具：只考虑我自己的这台 Mac 和我的使用习惯，不为公开发布做取舍。

## 三、目标

**一句话：任何地方，一个快捷键，把手头的文字交给合适的模型，用合适的提示词处理，结果可以直接用，也可以接着聊。**

1. **三个入口。** ⌥空格打开面板；双击 ⌥ 带着选中的文字打开面板并执行；⌥S 截图识别文字后带进面板。
2. **模式就是提示词预设。** 每个模式是一段提示词，加上默认模型和输出格式。内置翻译、润色（杂乱时顺带整理）、提示词梳理、问答四个，Tab 切换，可以自己加。
3. **Markdown 一等公民。** 结果按 GFM 流式渲染：表格、代码块（带高亮）、任务列表、引用、链接、公式；半截的语法在流式中就按最终样式显示，不闪烁。
4. **多轮对话。** 每个结果都能追问；问答模式直接以对话开始。会话只在内存里，不落盘。
5. **多模型。** 可以配置多个模型，每个模式指定默认模型。
6. **设置对 AI 友好。** 全部设置在一个带 schema 的配置文件里，改完立即生效；交给 Claude Code 之类的 agent 就能配好，并能自己检查。
7. **原生、轻、快。** 单一 Go 二进制，不抢焦点，唤起即现，常驻内存小。

## 四、设计原则

- **入口比功能重要。** 唤起要比任何动效都快；带入选区、截图这些入口要保证不抢焦点、剪贴板原样放回、不修改原应用内容。
- **模式而不是聊天窗口。** 多数时候要的是「把这段文字变成那样」，对话是结果之后的延伸（问答模式除外）。
- **结果可以直接用。** 复制出来的东西不需要再手工清理。
- **不做本机预处理，交给模型。** 终端输出的框线、截图识别的断行、语言判断这类情况枚举不完，用提示词让模型处理，不在本机写规则。
- **设置给 agent 改。** 配置文件就是接口：字段有 schema 说明，改完热加载，错了不崩溃并指出错处。
- **不存东西。** 不保存会话和原文，日志里没有文字；笔记是唯一的例外，因为它是我主动写下的；API Key 只在本机的配置文件里，不出现在任何输出中。
- **权限可选。** 没有辅助功能或屏幕录制权限时降级可用，不强求。

## 五、最终效果

### 面板

```
┌────────────────────────────────────────────────────────────────────┐
│ 原文 / 问题（多行输入，可粘贴）                                        │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 翻译 → English · 润色 · 提示词 · 问答     ◐ theme  tab 模式  ⏎ 执行   │
├────────────────────────────────────────────────────────────────────┤
│ 结果                                    模型 · Sonnet   复制 ⌘C ⌄   │
│                                                                    │
│ ## 会议纪要整理                                                      │
│ | 事项 | 负责人 | 截止 |                                              │
│ |------|-------|------|      ← Markdown 流式渲染                       │
│ ...                                                                │
│                                                                    │
│ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
│ 追问…                                                     ⌘⏎ 发送   │
└────────────────────────────────────────────────────────────────────┘
```

- 宽度固定，顶边固定只向下生长，到上限后结果栏内部滚动；出现在鼠标所在屏幕。
- 第一轮之后，结果栏变成对话流：每一轮是「追问 + 回复」，最新一轮在下面；底部是追问输入框。
- 问答模式下，原文栏就是提问框，⏎ 直接开始对话。

### 一天里怎么用它

| 时刻 | 操作 | 发生什么 |
| --- | --- | --- |
| 读英文文档 | 选中一段，双击 ⌥ | 面板带着这段出现，用默认模式（翻译）译成中文 |
| 图片里的图表 | ⌥S，框选 | 本机识别文字，带进面板翻译 |
| 一段从聊天记录复制的乱文本 | ⌥空格，粘进面板，Tab 到「润色」 | 整理成标题、列表和表格 |
| Claude Code 回了一大段英文 | 选中终端里的输出，双击 ⌥ | 译成中文，框线和硬换行由模型处理掉 |
| 写邮件时想润色一句 | 选中，双击 ⌥，Tab 到「润色」 | 润色后的文字在面板里，复制回去 |
| 脑子里有个模糊的需求 | ⌥空格，写下来，「提示词」模式 | 梳理成「背景 / 目标 / 约束 / 验收」结构的提示词 |
| 突然想确认一个命令的用法 | ⌥空格，Tab 到「问答」，输入问题 | 快速模型几秒内回答；不够清楚就追问 |
| 想加一个「写 commit message」的模式 | 让 Claude Code 改配置 | agent 读 schema、往配置里加一个模式，面板立即出现它 |

### 成功的标准

- 日常翻译、截图翻译和快速问答都能在 Gloss 内完成。
- 四个内置模式覆盖上表的场景，结果复制出来不需要手工清理。
- 唤起、带入选区和流式输出达到 [需求](requirements.md) §五 的延迟、帧率与资源占用指标。
