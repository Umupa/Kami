# 决策记录

每条记录写清楚决定、理由和放弃的方案。决定被推翻时，在原条目里写明新决定和日期，不另起重复条目。

## D1 重写，不 fork 辞达（2026-10-18）

**决定**：新建仓库，用 Go 重写；辞达只作为需求和设计的参考，不复制代码。

**理由**：
- 新场景碰到辞达的设计前提：它的提示词合约把输入一律当作材料，不当作指令，与问答、追问、提示词梳理冲突；结果栏是专为纯文本译文写的 TextKit 流式管线（`ResultTextView.swift` 约 1,300 行），加 Markdown 等于重写核心。
- 上游迭代很快（10 天 218 个提交），改动集中在 `AppModel`、`PanelView`，fork 后几乎每次同步都要解决冲突。
- 想换技术栈（Go + MyGo），fork 就只能写 Swift。

**放弃**：fork 后长期跟随上游；向上游提 Markdown 渲染。

**注意**：辞达是 Apache-2.0。参考它的规范和思路不受限制；如果移植具体代码，需要保留它的版权与许可声明。

## D2 用 MyGo 原生 UI，不用 SwiftUI，也不用 WebView（2026-10-18）

**决定**：界面用 MyGo 的 `ui` 包（Go 写、GPU 自绘、Core Text 排字），不用它的 WebView 模式。

**理由**：
- `ui/markdown` 自带为 LLM 流式回复设计的 GFM 渲染（增量解析、半截语法、匀速出字、淡入），正好是辞达缺的部分。
- 原生 UI 窗口打开即有内容、内存小，满足面板「按下即出现」。
- MyGo 已覆盖面板窗口、全局快捷键、菜单栏、钥匙串、透明穿透窗口、打包签名和更新。

**代价**：MyGo 很新；输入法与听写在自绘输入框上的表现要实测（见 tech-stack.md §九）。

**放弃**：SwiftUI + AppKit（成熟，但与想尝试 Go 的初衷不符）；MyGo WebView 模式（Markdown 生态更全，但唤起慢、内存大）。

## D3 系统 API 用 purego 直连，不用 cgo（2026-10-18）

**决定**：辅助功能、CGEvent、NSPasteboard、Vision、ScreenCaptureKit、NaturalLanguage 都通过 purego / purego/objc 调用，封装在 `internal/macos`。

**理由**：保持「纯 Go、无 cgo」，构建只要 Go；MyGo 自己就是这样调系统的。

**退路**：Objective-C block 或回调太难处理时，用 MyGo 的 helper executable 附带一个小的 Swift 工具，通过标准输入输出通信。

## D4 不保存会话（2026-10-18）

**决定**：会话、原文、结果只在内存里，退出即消失；日志不含文字。

**理由**：沿用辞达的隐私承诺；用户确认不需要保存提示词和历史。

## D5 把「动作」推广成「模式」（2026-10-18）

**决定**：模式 = 输入语义 × 提示词 × 语言规则 × 输出格式 × 默认模型 × 预处理 × 结果去处（architecture.md §三）。

**理由**：新场景之间的差别正好落在这几个维度上；辞达的动作只有提示词一个维度。

## D6 每个结果都可以追问（2026-10-18）

**决定**：多轮对话不是单独的窗口，而是任何结果之后的延伸；问答模式以对话开始。Material 模式的合约规定：第一条用户消息是材料，之后的用户消息是追问指令。

**理由**：多数时候用户要的是「把这段变成那样」，对话是对结果的调整；同时保住防注入。

## D7 开发期快捷键用 ⌃⌥，替换完成后改回 ⌥（2026-10-18）

**理由**：macOS 会把同一个热键同时发给所有注册了它的应用；过渡期两个应用并存。

## D8 自签名证书保证授权不丢（2026-10-18）

**决定**：自用阶段用本机自签名的代码签名证书。

**理由**：辅助功能和屏幕录制的授权绑定签名身份；临时签名每次构建都会变，授权随之失效。目前没有 Developer ID。

## D9 不依赖大模型 SDK（2026-10-18）

**决定**：`net/http` + 自写 SSE 解析器支持三种格式。

**理由**：只用到流式补全一个接口；三家 SDK 的依赖和行为差异不值得；与辞达的配置字段保持一致。
